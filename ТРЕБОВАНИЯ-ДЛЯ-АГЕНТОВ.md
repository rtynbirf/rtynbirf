### 1.2 Безопасность Actions (GitHub Docs, secure-use)
- Токены: OIDC и «short-lived, well-scoped access tokens» — «stop storing these
  credentials as long-lived secrets». Ротация: «Rotate secrets periodically».
- Минимальные права: «the credentials being used within workflows have the least
  privileges required»; GITHUB_TOKEN по умолчанию «to read access only».
- Пиннинг: «The best measure is to lock your workflow dependencies with a lockfile»
  (сильнее SHA-пиннинга); без lockfile — «Pin references to actions to a commit SHA».
- Недоверенный ввод: инъекция в скрипты — «Use an action instead of an inline script»
  или промежуточная переменная окружения; «Avoid using the pull_request_target
  workflow trigger if it's not necessary»; привилегированные воркфлоу
  «must not explicitly check out untrusted code». Это мировой аналог
 (prompt-injection) гигиены для агентных сценариев.
- Автоматам не давать «create or approve pull requests could be a security risk».

- **Правило 23 · СТАТУС = КЛЕЙМ.** Зелёный без свежего heartbeat-свидетельства —
  не клейм здоровья. Каждый крон несёт свидетеля: СТРАЖ-СПЯЩИХ.jsonl.
- **Правило 24 · ШРАМ-ПРОТОКОЛ.** Инцидент → шрам в KNOWN_ISSUES с ID прогона →
  патч → приёмка зелёным → правило. Класс косяка без шрама не закрыт.
- **Правило 25 · СЧЁТ = ТРИАНГУЛЯЦИЯ.** Публичное число несёт источник и метку
  свежести; канонический счёт — core API; расхождение источников публикуется
  в contradictions, а не прячется.
- **Правило 26 · ФЛОТ = ОРГАНИЗМ.** disabled_inactivity — болезнь: лечится
  (enable + dispatch). disabled_manually — приказ: не трогается, только
  пересчитывается. Активный крон, молчащий сверх порога, — тихая смерть:
  компенсация ручным диспатчем.
- **Правило 27 · ЗАКОН ОДИН — ИСПОЛНИТЕЛЕЙ МНОГО.** Центральная гвардия живёт
  в одном репо-источнике; копия гварди — инцидент.

## 3. Гейты входа агента (чек-лист)

1. Прочитай AGENTS.md (этот репо) и ТРЕБОВАНИЯ-ДЛЯ-АГЕНТОВ.md (этот файл).
2. Клейм без свежей улики (файл / прогон / API-ответ с датой) — не клейм.
3. Не трогай state-файлы руками (автомат/описи) — только через автоматы.
4. Пуш: commit → push первым; при отказе fetch + pull --rebase=merges, до 3 попыток;
   после пуша сверить, не перезаписал ли самописец.
5. Коммит-сообщение: что сделано + класс дефекта (если чин) + REVE=РЕВО.
6. Красное — честно красное: ДЕГРАДАЦИЯ/СОН/БОЛЕЗНЬ как состояния, не маска.
7. Секреты: в код не вставлять; маскировать; долгоживущие — на ротацию.
