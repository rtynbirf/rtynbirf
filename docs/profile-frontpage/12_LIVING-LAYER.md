# 12 · Живой слой дома: якорная система ФОРЖ

## Что это

Секция README «Живой слой дома» — не декорация, а исполнительная система доказательств.
Требование 07_DATA («одна метрика — один источник») и 06_EVIDENCE («клейм → свидетельство →
метод → область») в доме уже реализовано кодом: боты перезаписывают маркированные блоки
README из живого GitHub API, каждый блок несёт штамп времени и источник, а бейджи читают
committed JSON — «бейдж не может соврать».

## Инварианты (проверяет scripts/check_readme.py)

1. **Якорная целостность**: каждый `<!--X:НАЧАЛО-->` имеет `<!--X:КОНЕЦ-->`; состав якорей
   полный (10). Потеря якоря = FAIL приёмки — боты дома опираются на маркеры как на
   API-контракт перезаписи.
2. **Дословность блоков**: блоки переносятся байт-в-байт (сборка scripts/build_frontpage.py
   извлекает их из baseline регуляркой, без пересказов).
3. **Доступность**: каждая `<img>` несёт `alt=`; смысл страницы не зависит от картинок.
4. **Честность динамики**: при недоступности источника блоки показывают STALE/UNKNOWN,
   никогда — ручную подстановку (правило 23: клейм без свежей улики — не клейм).

## Отличие от внешнего аудита

Внешний пакет v1.0 (docs 01–11) не видел живой слой и предлагал редукцию первого уровня
как «обнуление счётчиков». Синтез (заход 7): скелет и дисциплина пакета сохранены, а
живые блоки собраны в одну секцию под явной политикой свидетельств. Редукция затронула
статический текст (27 заголовков → 9), живой слой сохранён полностью.

## ФАКТУМ: орган другого класса

С 25.11.2026 в живом слое есть блок «СЕРДЦЕ ДОМА · ФАКТУМ» — он не ФОРЖ-якорь, а embed
бейджа репо `factum` (raw `pulse.svg` ← committed `pulse.json`). Разделение писцов
(правило 27 в применении к данным): `JOURNAL.md` пишет только `factum-heartbeat`;
`pulse.json`/`pulse.svg`/`PULSE_LOG.md` пишет только `pulse-monitor`; профиль — только
читатель. Один файл — один писец: гонка писцов поймана шрамом KNOWN_ISSUES (45669803086).
