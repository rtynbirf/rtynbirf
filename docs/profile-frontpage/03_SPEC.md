# Техническое задание

## Цель
Перестроить профильный README `rtynbirf/rtynbirf` в компактную, достоверную и навигационно ясную точку входа, сохранив авторскую идентичность.

## Область
Включено: новый README, спецификация, карта проектов, политика доказательств, модель динамических данных, валидатор и критерии приёмки.

Не включено: изменение кода других репозиториев, изменение пинов профиля, массовое переписывание README, публикация/PUSH без отдельного согласования.

## Функциональные требования
- FR-01: одно название и одно точное определение в начале.
- FR-02: 3–5 быстрых маршрутов для разных намерений посетителя.
- FR-03: 4–6 кластеров с краткими определениями.
- FR-04: не более 5–7 флагманов на первом уровне.
- FR-05: полный каталог вынесен по ссылке.
- FR-06: существенные утверждения ведут к источнику и методу проверки.
- FR-07: динамические числа не редактируются вручную, если они вычисляются автоматически.
- FR-08: реализация, эксперимент, предложение, план и неизвестное состояние различаются.
- FR-09: сохраняются человекоцентричный принцип, автономность, офлайн-ориентация и орнаментальная идентичность.
- FR-10: ссылки и изображения доступны и имеют понятные альтернативы.

## Нефункциональные требования
- README отображается корректно в GitHub Markdown.
- Внутренние ссылки относительные.
- Нет секретов и приватных данных.
- Смысл сохраняется без изображений.
- Непроверенные свойства не объявляются подтверждёнными.
- Изменения имеют diff и rollback.

## Целевая композиция
1. Название и определение.
2. Быстрый вход.
3. Основные направления.
4. Принципы.
5. Проверка и достоверность.
6. Карта/состояние с источниками.
7. Участие и документация.

## Источники истины
GitHub — метаданные профиля; конкретный репозиторий — статус проекта; CI/тестовые артефакты — результаты проверок; утверждённый реестр — каталог; генератор и committed output — динамические показатели.

## Безопасность
Не удалять файлы автоматически; не менять default branch; не выполнять force-push; не подменять UNKNOWN на PASS; не публиковать без согласования владельца.

## Добавлено интеграцией (заход 7)

  сохраняются дословно; валидатор проверяет пары и полный состав (10 якорей).
