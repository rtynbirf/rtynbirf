# Политика утверждений и свидетельств

## Запись утверждения
Каждое существенное утверждение должно иметь: `claim_id`, текст, тип, scope (репозиторий/ref), evidence, method, environment, observed_at, result, limitations и verdict.

## Типы
DESCRIPTIVE, IMPLEMENTATION, FUNCTIONAL, PERFORMANCE, COMPATIBILITY, SECURITY, SCIENTIFIC, FUTURE.

## Раздельные оси
- Реализация: IMPLEMENTED / EXPERIMENTAL / PROPOSED / PLANNED.
- Проверка: VERIFIED / NOT_TESTED / UNKNOWN / REFUTED.
Не сводить их в один статус. Реализованное может быть не проверено.

## Уровни свидетельств
E0 — заявление; E1 — артефакт/статическая проверка; E2 — воспроизводимая команда; E3 — интеграционная/runtime-проверка; E4 — независимый внешний аудит. Это внутренняя шкала, не сертификация.

## Правило
Сила публичной формулировки не должна превышать силу свидетельства. Наличие SECURITY.md не доказывает безопасность; наличие benchmark-кода не доказывает производительность; наличие прототипа не доказывает готовность.

При изменении версии или commit старое свидетельство не переносится автоматически.
